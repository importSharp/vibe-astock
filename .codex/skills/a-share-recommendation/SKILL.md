# A股推荐 Skill

从项目根目录运行：

```powershell
.venv\Scripts\python.exe .codex\skills\a-share-recommendation\scripts\rank_first_boards.py --canonical
```

这是正式推荐的唯一入口：它与网站读取同一份15:35后生成的不可变快照，并返回策略规则指纹与候选结果指纹。若正式快照缺失，必须明确报错，不得改用实时数据给出另一份正式名单。

`--live` 仅用于诊断数据源和生成流程，不得把它的临时输出当作面向用户的正式推荐。先读取 [references/strategy-spec.md](references/strategy-spec.md)，再解释正式脚本输出。结构化候选只能来自脚本结果；不得凭印象增加股票。

## 必须遵守

- 只做当天收盘封住的真实首板，目标是次日 1进2；不输出 2进3。
- 核心交易目标是次日在首板晋级二板的过程中取得可成交仓位；二板成功后才进入博取三板及更高连板的持有阶段。不得把已经二板或更高的股票倒推成1进2候选。
- 股票范围只限沪深主板：上交所 `600/601/603/605`，深交所 `000/001/002/003`；创业板、科创板、北交所全部排除。
- 同时要求 `lbc=1`、`zttj.days=1`、`zttj.ct=1`。反包板不是标准首板。
- 每日使用“3+2”：3是固定展示的三只次日1进2预测候选，直接标为优先级1—3；2是最多两只已经二板或更高的高标观察锚，用于验证市场高度和板块承接，不占三个候选席位。
- 三只候选统一从同一首板池按“涨停潜力70%＋可买性30%”计算加权总分并排序，不再为趋势、情绪或自由席预留名额；同一板块最多两只。
- 只提供候选、所属板块、相对排序、两项分数及可买性说明。具体买点、是否追高、是否等待回封和最终是否参与由用户自行判断，报告不得替用户规定精确买入价或机械买点。
- 三个席位是预测排序，不代表三只都应交易；必须保留公告风险、板质缺陷和数据缺失提示，但不得用市场总闸门清空固定三股名单。
- 两只高标观察锚优先包含“全市场最高连板”和“与三个候选所属板块相关的最高连板”；若相关板块没有连板股，则使用市场次高标。高标不足两只时如实少列，不拿普通首板补足。
- 高标观察锚不受40元买入价格限制，因为它们绝不进入购买名单；但必须是沪深主板连板股，创业板、科创板和北交所不用于判断本策略的10cm接力环境。
- 次日高标表现只作为情绪背景，不能单独否决三个1进2候选。高标失效必须与板块宽度收缩、无新首板、指数/资金同步转弱等至少一项群体证据共同出现，才可降级相关板块；单只高标失败只记录该股失败。
- 排名首先比较70:30加权总分；总分相同时依次比较涨停潜力分、可买性分。不得为了席位结构或板块分散把总分更高的股票换成较弱股票。
- 买入池优先覆盖至少两个板块，同板块最多两只。质量优先于板块数量，不能为了分散而加入低质量股票。
- 收盘价与次日实际委托价都必须严格低于 40 元；等于 40 元也排除。
- 盘后候选不等于次日必买；报告负责推荐最可能1进2且具有一定可成交性的三只，盘中买点由用户判断。
- 本 Skill 是盘后推荐系统，不要求用户在盘中再次咨询。收盘后一次性完成候选、板块逻辑、次日路径风险和预计可参与性等级；次日观察与执行完全由用户自行完成。
- 排名只使用两项：涨停可能性70分、可买性30分。涨停可能性是主排序，必须同时考察板块趋势、涨停梯队宽度、板块当前连板高度、个股首板质量和可核实催化；可买性只作门槛与同分排序，不能让“容易买但接力弱”的股票排到梯队核心之前。
- 板块结构必须区分“成熟梯队延续”“首板扩散”“低位发酵种子”和“梯队过渡”。成熟梯队与低位发酵使用同一14分结构上限；低位发酵只能获得有限结构分，不能仅凭新题材身份强行进入前三。
- 三只正式候选之外，另列最多3个“发酵观察”方向，每个方向只列一只真实首板种子。该雷达用于避免只盯昨日热点，不是额外买入名单，不改变3+2席位。
- 市场模式只作为风险背景和涨停潜力评分的一部分，不得改变70:30权重，也不得在弱市改用另一套排名公式。上涨家数、晋级率、炸板率和涨停数量变化必须展示，供用户自行决定是否参与。
- “避险”只表示弱市中的相对抗跌与资金承接，不表示本金安全。防守候选必须同时满足：所属板块弱市相对强、资金没有由净流入快速转为流出、个股处于板块前排、回踩缩量且重新站稳前收与分时均价。未同时满足时放弃。
- 新闻热度不加分。公告或资讯命中“风险提示、停牌核查、暂停相关投资者账户交易、严重异常波动”时，个股直接降为观察，不能进入三个买入候选。
- 板块单日涨幅达到4%或净流入达到100亿元时标记“单日过热”，在原始涨停分中扣3分；没有连续2—3日资金与强度数据时必须写“单日趋势未验证”，不得把单日爆发直接当成持续趋势。
- 优先选择有板块梯队且可能成为前排/容量核心的首板，降低孤立涨停的排名。后续连板潜力不能覆盖次日可买性不足；买不到的一字板仍然不是合格交易候选。
- 个股与板块必须分层否决：某只股票晋级失败、炸板或跌破确认位，只否决该股票，不能据此把整个板块判为走弱。只要板块仍同时存在高度板和新首板，就必须保留“梯队活跃”状态。
- 板块降级至少需要两项群体性证据同时出现：高度板整体失败且没有替代高度、当日无新首板或首板数量明显收缩、涨停宽度降至1只以内、板块指数与资金同时转弱、多个板块成分股集体失效。单只股票失败不计作板块否决。
- 三只候选必须展示涨停潜力70分、可买性30分和总分；分数用于相对排序，不伪装成真实概率。公告硬风险可将股票标记为风险样本，优先由无硬风险股票补位。
- 信息只引用 a-stock-data 返回的涨停原因、概念、新闻和公告。数据缺失时明确写“未验证”，不得补写。
- 给每只候选解释选择板块、选择个股和可买性评分依据；不再给精确买点。另列最多2只高标观察锚，写明板数、所属板块和观察作用。
- 高标观察锚只提供确认或否决信号，永远不能升级为本策略的1进2候选。
- D2—D3板块孵化可以作为后台复盘标签，但不得占用3+2中的任何席位，也不得影响当天三个1进2候选的身份。
- 不承诺涨停、胜率或收益；每天固定展示3只预测样本和条件，但不得替用户完成最终买入决定。
- 09:25—09:35过早封死、零炸板的股票仍降低可买性，但只要当日存在真实成交与换手，不得与一字板等同处理。
- 次日高开超过5%不再自动否决候选；高开幅度、是否一字和盘中换手由用户自行用于买点判断。报告只需提前说明可能难以成交或追高风险。
- 每只候选必须根据当日首封/回封时间、开板次数、换手率和成交额，标注次日路径类型与预计可参与性等级：`秒板难买风险/C`、`早盘冲板分歧风险/B-`、`换手接力倾向/A`、`普通接力路径/B`或`尾盘延续风险/C`。这是盘后风险画像，不是盘中买点或保证。
- 推荐复盘必须把“涨停命中”“存在可成交窗口后涨停”和“触板未封”分开统计。买不到的快速封板不能算可交易命中，触板炸板也不能算涨停命中。
- 另记“用户可执行涨停命中”：次日曾进入+1%至+3%的向上或稳定换手窗口，随后收盘封住涨停。始终高于+3%、直线下杀后急拉或只有瞬时窗口的股票，不计入该口径。
- 高标观察锚只提供市场环境信息，不得机械否决全部候选。只有板块宽度、梯队、指数/资金等至少两项群体证据同时恶化，才可对相关板块降级。
- 每个交易日收盘后必须把涨停池、板块资金、市场情绪、完整候选排名和最终输出写入同日不可变JSON快照。历史回放只允许读取对应交易日快照；缺少快照时必须明确报错，禁止拿当前板块资金或当前情绪补算历史推荐。
- 每个交易周期固定输出两份结果：15:35后的盘后三只候选，以及下一交易日09:25对同一组三只的竞价确认。竞价结果只能重新排序并标记“竞价确认、等待换手、竞价淘汰、数据不足”，不得换入盘后名单外股票。
- 竞价确认使用候选竞价涨跌幅、所属行业昨日涨停股联动、昨日涨停股整体竞价中位数与行情覆盖率。腾讯L1不提供逐笔撤单和真实未匹配单，缺少这些数据时必须明确披露，不能伪装成已验证。

## 固定展示字段

每只预测候选必须完整出现以下字段，缺少任何一项都视为输出不合格：

1. 股票名称与代码
2. 主行业与题材评分板块（必须分开，不能把概念题材写成唯一行业归属）
3. 1进2优先级：1 / 2 / 3
4. 状态
5. 选择该板块与该股票的理由
6. 高标观察锚单独成表（名称、代码、板数、所属板块、观察用途与失效信号）；整份报告最多2只
7. 可买性说明，不提供具体买点
8. 封板类型（过强硬板/换手首板/普通首板/尾盘板）
9. 涨停可能性分与可买性分
10. 板块涨停家数、新首板家数、当前连板高度与板块健康状态，用于解释二板之后是否具有继续连板的环境
11. 市场背景和资金确认字段
12. 次日路径类型、预计可参与性等级及其盘后证据
13. 板块阶段，以及最多3个独立的低位发酵观察方向
14. 下一交易日09:25对原三只候选的竞价状态、竞价涨幅、行业同批均值和二次排序

## 数据异常

若涨停池日期不是最近已收盘交易日、关键市场数据缺失、板块数据为空或接口日期不一致，停止给出“可考虑”结论；若基础首板数据仍完整，可继续列出3只预测样本但必须标记“数据异常、仅观察”，并写明缺失项与数据时间。

涨停池、行业资金/市场广度和短线情绪的交易日期必须完全一致，且当日15:35后才允许落盘。日期不一致或盘中运行只返回临时结果，不生成快照。
