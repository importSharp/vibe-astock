# 推荐数据快照与发酵雷达设计

## 问题

历史日期的涨停池可以按日期查询，但行业资金和市场情绪接口返回当前/最近数据。旧实现把两者直接拼接，导致第二天重跑昨日推荐时排名变化，并让复盘误以为昨日已经看见了今天才出现的板块强度。

同时，评分偏重已有连板高度和涨停宽度，容易集中到昨日成熟热点，对只有一只优质首板、尚未形成梯队的新方向缺少展示。

## 方案

1. 每个交易日15:35后，将涨停池、行业资金/广度、短线情绪、完整排名和最终输出保存成按日期命名的不可变JSON。
2. 落盘前校验三类输入属于同一交易日；不一致或盘中运行只返回临时结果。
3. 历史请求先读取目标日快照；缺失时拒绝重算，明确提示无法用当前数据补历史。
4. 板块结构新增成熟梯队、首板扩散、低位发酵种子和梯队过渡四个阶段。
5. 低位发酵可获得有限结构分，并在正式3+2之外展示最多3个观察方向；不强制占用前三。
6. 复盘增加用户可执行涨停口径，避免把理论封板但实际几乎无法参与的股票算成策略成功。

## 验收

- 同一日期重复保存不能覆盖首份快照。
- 历史日期缺快照必须报错，不能访问实时接口后重算。
- 昨日快照在次日读取时输出保持一致。
- 低位新方向可进入发酵雷达，但正式候选仍固定三只并按70:30排序。
- 现有真实首板、主板、40元以下和3+2规则不变。
